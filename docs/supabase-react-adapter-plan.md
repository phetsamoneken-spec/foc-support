# React/Auth adaptation plan — no production integration in Phase 1

1. Define a typed business/account repository boundary around `src/services/storage.ts`. Keep existing GAS functions/default backend active; introduce a Supabase adapter behind a deployment-owned, default-off selection. Do not let localStorage select a privileged backend or authorization role.
2. Add a pinned supabase-js dependency/lockfile only in the integration phase, with publishable project URL/key in frontend build config. Never introduce service-role credentials. Supabase Auth uses email/password unless the owner approves a rate-limited server-side username adapter; never authenticate by username alone or use a client-selected team as authorization.
3. Replace remoteAccounts GAS opaque sessions only inside the new adapter. Auth API verifies the actual user; load active mkt_profiles for display, while database RLS/RPC remains authoritative. Keep legacy sessions isolated by adapter and actor; reject responses arriving after logout/account change. Test reset, disabled user, role/team changes, JWT refresh and revoked sessions.
4. Read customers/conditions/contracts/budgets/transactions with stable source text IDs. Join customer names; compute contract status from Asia/Vientiane business date and alert settings. Read financials through mkt_budget_totals; do not copy UI totals back to tables. Map decimals deliberately into presentation formatting, preserving decimal precision in write transport.
5. Translate businessWrites kinds to mkt_mutate operations. SAVE_BUDGET supports first creation and explicit annual period editing for both roles. UI needs selected period, missing-budget action and version token. Existing UPDATE_BUDGET propagates future periods; draft RPC edits one year, so confirm policy before implementing UI behavior. Admin exception approval stays separate and reason-required.
6. ADD_TRANSACTION/CANCEL_TRANSACTION use the relevant budget version. On SQLSTATE 40001 refresh the latest authoritative snapshot and let the user review/retry a **new** operation. Lost-response retries reuse the exact operation ID/payload/version, returning the saved receipt. Never modify payload while keeping the same operation ID. Add server-returned version/snapshot on integration if desired; current RPC returns the entity ID and operation receipt only, then the adapter refetches.
7. Preserve business snapshots, pending Sheet publication and original GAS outboxes through migration. Scope a new Supabase outbox by project+auth actor+adapter version. Do not auto-send GAS outbox operations to Supabase. Reconcile devices first and retain acknowledged private recovery exports. For ordinary Supabase retries keep original operation IDs.
8. Implement separately reviewed Admin server functions for accounts/configuration/categories/imports. Teams need a safe shared-settings read endpoint because raw mkt_settings is Admin-only. Validate settings using the existing sharedSettings allowlist/ranges; keep routing credentials outside that response. Audit every privileged operation and validate current Admin profile/session. No service key in browser.
9. Offline PWA may display previously cached own-team data but must mark it stale. No offline authorization guarantee: queue writes until server confirms. Clear visible scoped caches on logout/account change while retaining protected unresolved outboxes under their original owner for reconciliation. Prevent service-worker precaching of private API responses and test cache isolation.
10. Verify the existing suites plus adapter contract tests, real Auth enrollment/login, RLS Data API reads, budget create/edit, yearly reports, import preview/approval, pending-write races, cancellation, browser recovery and private rollout/rollback. The review branch already removes the obsolete build docs-copy step to preserve these tracked Markdown files. Request a separate production DB/import/deployment approval only after staging evidence is reviewable.

No adapter, dependency, login UI, GAS endpoint or PWA behavior is changed by this review branch.
